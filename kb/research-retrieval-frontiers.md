# Retrieval Frontiers for Phase 3 Recall

## TL;DR

Top-K cosine over a single Gemini embedding is **not** the right default for this architecture. The recall layer is conditioned on `surrounding_context` (multi-segment, entity- and time-anchored, agent-role-typed), gated by correctness invariants (predicate exclusion, consent_basis, derivation-orphan), and supervised by engagement — none of which a single pooled cosine captures. The recommended architecture is a **layered pipeline**: hybrid BM25 + Gemini-001 asymmetric dense candidates fused by RRF → hard correctness gates → full-3072d rescore plus multi-feature scoring with multiplicative gates and additive soft features → instruction-following cross-encoder rerank → MMR diversification inside a 12-item brief cap, with every step logging propensities into the recall-log so future engagement-trained ranking is possible. The key risk: every layer depends on Gemini-embedding-001's task-type asymmetry (silently dropped by most SDKs and by gemini-embedding-2), so the pipeline must call REST `embedContent` directly and pin the embedding model version in every event.

## The question and why it matters

`<checkout>/kb/thesis.md` explicitly anti-reinforces raw surfacing — engagement, not retrieval frequency, is the supervisory signal — and `<checkout>/kb/architecture.md` defines `surrounding_context` as the *projection* a memory event is asked about, not a simple query string. That projection includes `current_query`, `recent_turns[]`, `agent_role`, optional time anchors, and downstream features (entities, valence). Pooling that into one vector and asking ANN for top-K destroys exactly the structure the architecture pays for. The predicate ledger (`PREDICATE_MAX_ACTIVE=1024`), `consent_basis`, and `derivation_graph` are not features the ranker may override — they are invariants. And the ledger is event-sourced, append-only, with per-`embedding_model_version` indices, so recall must work *during* a model migration, not only after. The frontier question is therefore: given Gemini-001's asymmetric task-typed embeddings as the unique edge (Phase A), what is the *cheapest* layered pipeline that respects every invariant, captures multi-segment context, and produces a recall-log whose propensities can later train a learned ranker without re-architecture?

## Direct answer

**Top-K cosine on a single pooled Gemini embedding cannot satisfy this architecture's load-bearing primitives.** Five reasons. (1) `surrounding_context` is multi-segment with entities, time anchors, `agent_role` and `recent_turns[]`; pooling smears proper nouns and time tokens that BM25 and per-segment encoding catch (f1, f2). (2) Hard gates — predicate exclusion, `consent_basis` dampening, derivation-orphan flags — are correctness invariants that must run as multiplicative gates around the score, not as features a high cosine can override (f6, f8). (3) The recall-log is engagement-gated: raw surfacing is explicitly anti-reinforced (`thesis.md:30`), so engagement labels, not cosine, are the supervisory signal (f6, f8). (4) Production cosine-top-K systems (ChatGPT memory, LangGraph Store) exhibit the exact failure modes the thesis names: persona drift, stale-strategy injection, project contamination (f11). (5) Time is conditional: anchor-matching is a separate channel; evergreen facts must not decay like episodic ones (f9). What beats it: **hybrid candidate generation (BM25 + asymmetric Gemini-001 dense, RRF-fused) → hard gates → full-3072d rescore with multi-feature scoring (multiplicative gates around an additive soft-feature sum) → instruction-following cross-encoder rerank → MMR diversification within a 12-item brief cap**, with propensity logging from day 1 so engagement-trained ranking arrives later without a re-build.

## Recommended Phase 3 architecture

**Layer 1 — Candidate generation (hybrid).** BM25 (Lucene/Tantivy/`bm25s`, k1=1.2, b=0.75) over `event.content`, plus a secondary inverted index on `event.features.entities`, runs alongside an HNSW ANN over Gemini-embedding-001 `RETRIEVAL_DOCUMENT` vectors MRL-sliced to 768d and **L2-renormalized** (the Phase A renorm trap is load-bearing). Take top-50 from each leg; fuse with Reciprocal Rank Fusion (k=60, per Cormack 2009). The dense leg encodes each segment of `surrounding_context` (`current_query`, each `recent_turn`, `agent_role`, resolved time anchor) separately as `RETRIEVAL_QUERY` vectors; the per-candidate dense score is **max-sim over segment vectors** (per-segment MaxSim from f2), not a single pooled cosine. The ANN index is partitioned per `embedding_model_version`.

**Layer 2 — Hard gates and rescore.** After RRF fusion, apply hard correctness gates *before* rerank: predicate exclusion via snapshot-embedding match against the active predicate set (server-side filter, `PREDICATE_MAX_ACTIVE=1024`); `consent_basis=CONSENT_BLOCKED` dropped; `derivation_orphan` flagged (not dropped — reranker demotion). Then full-3072d cosine rescore the survivors. Multi-feature score is `(s_emb_full3072 * predicate_mask * consent_dampener * derivation_status * episodicity_match) + w_ent*entity_overlap_jaccard + w_t1*time_anchor_match (gated to 0 if no anchor) + w_t2*power_law_decay(age, kind) + w_val*valence_compat + w_eng*engagement_prior`. Decay is Wixted & Ebbesen 1997 power-law `m*(1+h*t)^(-f)` with per-kind `f`, **not** MemoryBank's exponential. Bootstrap weights: `w_ent=0.7, w_t1=1.5 (active), w_t2=0.3, w_val=0.2, w_consent=-0.5 for third_party_inferred`.

**Layer 3 — Reranker.** Instruction-following cross-encoder over the top-50 — Voyage rerank-2.5-lite or Gemini 2.5 Flash listwise, chosen by A/B on logged recall events, not benchmarks (f3 verifier DOWNGRADE). The instruction string encodes most of the policy declaratively: `agent_role`, time, prefer-entity-overlap, dampen `third_party_inferred`, demote `derivation_orphan` unless query is about deletions, avoid paraphrases of `recent_turns[]`. Output top-12.

**Layer 4 — Diversification.** MMR (Carbonell & Goldstein 1998) at λ=0.7 — *not* LangChain's 0.5 default; the candidate set is already pre-filtered (f4). Relevance term is the full multi-feature score; redundancy term is cosine on embeddings only (avoids double-penalizing entity/time). Final brief obeys ≤12 items, ≤4000 chars total, ≤600 chars/item. If average pairwise cosine over the selected 12 exceeds 0.85, or more than 6 items pass the relevance bar at similar scores, emit `density_flag=crowded`. Migrate MMR → k-DPP greedy with incremental Cholesky (Chen et al. 2018) once the recall-log has ~10^4 engagement events.

Predicate gates must **never** become learnable features the ranker can override — they are correctness invariants forever.

## Gemini integration specifics

**Model.** Gemini-embedding-001 only. Phase A verified that gemini-embedding-2 silently ignores `taskType` (cosine 1.000000 across `RETRIEVAL_QUERY`, `RETRIEVAL_DOCUMENT`, `SEMANTIC_SIMILARITY`, no-task on identical strings). 001 honors the 8-task taxonomy; that asymmetry is the system's unique edge over OpenAI/Voyage/Cohere/BGE. Revisit v2 only after Google stabilizes task-types and an explicit held-out A/B passes the predicate-gate suite.

**Task-type strategy (asymmetric).** Promote-time: encode fact content as `RETRIEVAL_DOCUMENT`. Recall-time: encode each `surrounding_context` segment as `RETRIEVAL_QUERY` by default; switch to `QUESTION_ANSWERING` when `recent_turns[]` ends in a literal question and `FACT_VERIFICATION` for verification-style recall. Phase A reported margin +0.1119 vs +0.0826 symmetric (~35% larger separation). **Round 18 empirical investigation (see `kb/asymmetric-margin-investigation.md`) identified H2 as the root cause** of the apparent magnitude collapse seen in the v0 integration test: Phase A's +0.1119 was *matched-minus-distractor separation* (cosine to the right answer minus cosine to a near-miss distractor — the metric that actually predicts retrieval quality); the v0 Step-7 assertion measured *RQ-vs-SS single-doc delta* (asymmetric vs symmetric cosine on the SAME pair — a smaller magnitude under any model). **The CI invariant is direction (asymmetric > symmetric), not magnitude.** Magnitude is pair-dependent and naturally ranges 0.0-0.15 across string types; the integration test should be renamed to clarify it tests direction, and a separate matched-vs-distractor margin metric (>0.05 floor) belongs in the held-out eval bootstrap at v1 — not the CI gate. Call REST `embedContent` directly; Semantic Kernel, LangChain `VectorStoreRetriever`, and LiteLLM proxy silently drop `task_type` and eliminate the entire advantage.

**MRL strategy.** Store full 3072-d at promote-time. First-pass ANN at 768-d MRL slice (~25% storage, ~0.26% MTEB loss per Google's numbers; top-1 stable down to 128d in Phase A tests). Rerank top-50 against full 3072-d in Layer 2. **Critical invariant**: 001 returns unit-norm vectors *only* at default 3072 dims; sliced vectors at 1536/768/256 have norms 0.70/0.59/0.39 and must be L2-renormalized before dot-product-as-cosine. Encode `||v||=1.0 ± 1e-6` as a pipeline-wide invariant; fail closed on violation. (Critic §1 flags binary/int8 quantization as an unexplored axis — defer until 10^5+ facts justify the trade-off.)

**Batch / latency / cost.** Bulk promote-time ingest via `asyncBatchEmbedContent`, batched by `task_type`. Input cap 2048 tokens; promote-time facts are typically ≤80 tokens (non-binding), but recall-time must distill `surrounding_context` to a focused query string before encoding, with the BM25 leg as anchor for entities the distiller may drop. Per `embedding_model_version` index, append-only re-embedding under new versions; never overwrite in place.

**Fallback (two-level).** (1) Transient outage: cache 24h of fact embeddings locally; the cascade routes uncomputable rows to the EMBED_DEFERRED outcome (cursor-park) and the next tick retries — no promote-time partial fact is written (the retired R29.3 promote-time write path is recorded in `kb/legacy-archive.md § R29.3`). Recall-time falls back to BM25-only candidate generation + reranker (different API surface); brief still emits with `degraded_recall=true`. (2) Sustained outage or consent escalation: zerank-1-small (Apache 2.0, ZeroEntropy) as a fully-local reranker for sensitive memories where external API calls are policy-blocked. Defer ColBERTv2 / SPLADE-v3 / ColBERT-XM unless empirical multilingual or lexical failure is measured — they would force abandoning the task-type advantage.

## Evaluation framework

**Offline (primary).** Recall@12 over a user-labeled held-out set of 150+ recall events stratified by `(agent_role, time-of-day, recent_recall_density)` — the headline because it matches the brief cap. MRR-expected (mean reciprocal rank of the first `expected_id` within `surfaced[]`). NDCG@12 with graded relevance: +2 `expected_ids`, +1 derivation-graph neighbors of expected_ids, 0 otherwise, **−2 `forbidden_ids`** (negative gain — encodes the asymmetric harm of mis-recall). Abstain F1 over `density_flag`/empty-brief emissions vs `abstain:true` labels (LongMemEval ability #5). Harm rate (any `forbidden_id` in a brief) — hard alarm on any positive. Plus invariants: predicate-exclusion correctness must be 100% on a synthetic test set; L2-renorm `||v||=1.0 ± 1e-6` on every embedding flowing through the pipeline; latency p50/p95 per layer and end-to-end.

**Online (trend).** Engagement-conditioned utility ECU per recall = Σ over surfaced (`engaged_positive` − 0.5·`engaged_corrective`), aggregated weekly **as a Mann-Kendall trend with paired-bootstrap CI on slope** (critic §6). Fraction of recalls with any engagement (sparsity / cold-start gating signal for v3). Fraction with any dismiss/correction (harm rate). `density_flag` rate vs user-judged crowding (calibration). Recall-log volume per day and `embedding_model_version` coverage are **health metrics, not quality metrics** (they rise monotonically with effort regardless of quality — critic §6).

**Bootstrap plan.** Two-week passive collection at v0 (no eval, just log everything *with propensities*). Week 3: sample 150 recall events stratified by `(agent_role, time-of-day, recent_recall_density)`. User labels `expected_ids[]/forbidden_ids[]/abstain:bool` in batches of 20 (~15 min/batch, ~2 hours total — feasible but not free; critic §5). Labels stored as `held_out_label` events `derived_from` the recall event — the held-out set is itself event-sourced and auditable. Run all four offline metrics with paired-bootstrap 90% CI over 10k resamples vs Phase 0. **Refuse to claim improvement unless CI excludes zero.** Re-grow held-out set quarterly; alert if median label age > 90 days. Ranker-vs-ranker decisions use team-draft interleaving (Chapelle 2012) over ≥200 paired briefs (single-user noise reduced by within-session pairing). New ranker variants require OPE (Kiyohara 2023) on logged propensities **before** any live swap — propensity logging from v0 is the load-bearing prerequisite. Without it OPE is biased to uselessness.

## Risks + open questions

| # | Risk | Mitigation |
|---|---|---|
| 1 | **Renorm trap** — Gemini-001 returns unit-norm only at 3072d; MRL-sliced 768d has `\|\|v\|\| ≈ 0.59`. Silently breaks dot-product-as-cosine. | L2-renormalize every sliced vector. Automated `\|\|v\|\|=1.0 ± 1e-6` invariant check at every layer; fail closed. |
| 2 | **SDK task-type drop** — Semantic Kernel, LangChain `VectorStoreRetriever`, LiteLLM silently drop `task_type`, eliminating the asymmetric advantage. | Call REST `embedContent` directly. CI integration test round-trips a known asymmetric pair and asserts the margin separation; fail CI if a refactor regresses it. |
| 3 | **Gemini v2 migration trap** — v2 silently ignores `task_type` (cosine 1.000000 across all task types). | Pin gemini-embedding-001 in config; `embedding_model_version` on every event; migration to v2 requires explicit A/B + held-out gate, not a config change. |
| 4 | **2048-token input cap** vs long multi-turn `surrounding_context`. | Distill `surrounding_context` to focused query string before recall-time encode; BM25 leg anchors entities the distiller drops; per-segment encoding (f2) further mitigates. |
| 5 | **Park et al. additive equal-weight is the cargo-cult choice** — verifier REFUTED multiplicative characterization; ACAN 2025 follow-up beat it (5.94 vs 5.05). | Multiplicative gates around additive soft-feature sum; hand-tuned weights v0; learned at v3. Park as baseline, not destination. |
| 6 | **CLTR insufficient at single-user scale** — Oosterhuis & de Rijke 2024: 5 sessions/query CLTR fails; 100 needed; this system has ~1. | Stage learned ranking — v0 hand-tuned + RRF → v3 GBDT lambdarank with IPS only after ~10^4 engagement events. Never CLTR-from-scratch. |
| 7 | **Long-context-as-recall is uneconomic** — f7 REFUTED: ~6 orders of magnitude more expensive than RAG; multi-needle drops to 89% on frontier models; cannot apply hard gates inside opaque context. | Never as candidate-generation mechanism. Permitted only as optional cross-document synthesis over the bounded brief — separate concern. |
| 8 | **Reranker benchmark mismatch** — f3 DOWNGRADE: Voyage MAIR / ZeroEntropy 17 datasets do not benchmark multi-turn time-anchored conversational recall. | Don't lock in on benchmarks. A/B Voyage rerank-2.5-lite vs Gemini 2.5 Flash listwise on logged events from week 4+; choose by ECU and held-out NDCG@12. |
| 9 | **Cosine-top-K leaks** — persona drift, project contamination, stale strategy (f11). | Engagement-gated reinforcement demotes stale; predicate exclusion gates contamination; derivation graph propagates excise; density_flag prevents over-surface. Each gets a dashboard metric. |
| 10 | **A-MEM-style memory evolution destroys provenance.** | Reject in-place rewrites. Reflection/promotion writes a NEW event with `derived_from[]` populated; parents stay immutable; semantic promotion is corroboration-gated (≥3 distinct `source_refs`). |
| 11 | **Position bias is from LLM attention, not user gaze** — web-search PBM propensity tables don't transfer. | Re-estimate propensities from logged data via intervention harvesting + 5% jitter from day 1. Do not import Joachims 2017 Table 1 wholesale. |
| 12 | **Two-stage credit assignment** — engagement is the LLM's choice of what to quote, validated by the user. | Only count `engagement_positive` when the *user* (not the LLM's first draft) acknowledges the memory. Engagement listener must distinguish user-initiated agreement/correction from LLM-internal surfacing. |
| 13 | **Held-out staleness** as ledger drifts. | Re-grow held-out set quarterly with stratified sampling; track label-age distribution; alert if median > 90 days. |
| 14 | **Predicate-as-feature drift** — a learned ranker could discover overriding a predicate sometimes correlates with engagement. | Predicate exclusion is a hard gate *outside* the learned ranker forever. Engagement on excluded memories triggers a `predicate_review_request` MCP affordance, not a ranker-side learning signal. |
| 15 | **LLM-as-judge self-preference** when judging a Gemini-based ranker with a Gemini judge. | Use a different model family (Claude or GPT-4o); dual-order presentation; length normalization; LLM-judge only as tiebreaker between rankers with overlapping CIs. |
| 16 | **ColBERT/SPLADE temptation** — appears to subsume per-segment matching but discards Gemini task-type advantage. | Defer ColBERTv2/SPLADE-v3 entirely unless empirical lexical or multilingual failure is measured. Per-segment MaxSim over Gemini segment-encoded vectors captures most of the late-interaction win at the right granularity (f2). |

**Open questions surfaced by Phase E (critic):**
- **Binary / int8 quantization** is missing from the MRL trade-off. Defer until 10^5+ facts, but flag as a known unexplored axis (critic §1).
- **Symbolic-first (entity-linker → KB-restricted dense)** path was not researched; the v0 pipeline folds entities into BM25 only (critic §1).
- **Open-weights cross-encoder baseline (monoT5 / cross-encoder distillation)** was not researched as a Voyage/Flash alternative (critic §1).
- ~~**The "+0.1119 vs +0.0826" Phase A margin**~~ — **RESOLVED round 18**: matched-minus-distractor separation, not RQ-vs-SS single-doc delta. CI asserts direction only; magnitude metric belongs in v1 held-out eval. See `kb/asymmetric-margin-investigation.md`.
- **Per-kind power-law `f` priors (0.15/0.35/0.6)** remain load-bearing and not adversarially re-verified — re-measure before they harden as defaults (critic §2).
- **Predicate-snapshot-embedding scaling to 1024 active predicates per query** is asserted, never benchmarked against an ANN backend's filter-pushdown cost (critic §2).
- **"~10^4 engagement events ≈ 6–12 months"** assumes 10% engagement on 10^3–10^4 recalls/day — f8 itself flags two-stage credit ambiguity (critic §2).
- **TempRetriever citation** says "+6.86 Top-1" but the paper reports **+6.63% Top-1** (also +3.79 NDCG@10) — correct in citations list (critic §3).
- **Recall behavior across coexisting `embedding_model_version` indices** is unspecified (RRF across versions? re-encode-on-read? lazy background migrate?). Resolve before first version bump (critic §4).
- **`memory_excise` transitive propagation through derivation_graph at recall time** — orphan flag is not the same as transitive excise; v0 already needs this, not v2 (critic §4).
- **`query.mood` / valence channel provenance** — silent dependency on an upstream NLP component (critic §4).
- **v0 propensity distribution must be defined explicitly** (e.g. Plackett-Luce over softmaxed scores with temperature τ), not just "5% jitter" — otherwise OPE at v3 is dead (critic §5). Reflected in the v0 deliverables row above.
- **"ECU improves weekly trend"** needs a statistical test — Mann-Kendall over ≥8 weeks with paired-bootstrap CI on slope (critic §6). Reflected in v3 success criteria.

## Citations

1. **Cormack, Clarke, Buettcher (SIGIR 2009)** — *Reciprocal Rank Fusion outperforms Condorcet and individual Rank Learning Methods.* <https://plg.uwaterloo.ca/~gvcormack/cormacksigir09-rrf.pdf>. Defines RRF k=60, the no-training-data fusion the recall layer uses at v0/v1 before recall-log can identify a convex-combination α. Default in OpenSearch / Azure / Atlas / Weaviate.
2. **Bruch, Gai, Ingber (TOIS 2023)** — *An Analysis of Fusion Functions for Hybrid Retrieval.* <https://arxiv.org/abs/2210.11934>. Establishes that convex-combination of normalized scores beats RRF when training data exists — the destination for v3 once ~500 engagement-labeled events accumulate.
3. **Park et al. (2023)** — *Generative Agents.* <https://arxiv.org/abs/2304.03442>. Canonical multi-feature memory scorer. Verifier REFUTED multiplicative characterization — additive equal-weight, ACAN 2025 already beat it. Baseline-to-beat, not destination.
4. **Zhong et al. (AAAI 2024)** — *MemoryBank.* <https://arxiv.org/abs/2305.10250>. Introduces recall-updates-strength (`S←S+1, t←0`) and `cos × retention` multiplicative gate — conceptual precedent for engagement-gated reinforcement. We replace exponential decay with Wixted power-law and gate on engagement, not raw surfacing.
5. **Wixted & Ebbesen (1997)** — *Genuine power curves in forgetting.* <https://link.springer.com/article/10.3758/BF03211316>. Power-law (not exponential) as correct functional form at individual-subject level. Anchors `m*(1+h*t)^(-f)` decay; per-kind `f` differentiates fact/episodic/ambient.
6. **Abdallah et al. (2025)** — *TempRetriever.* <https://arxiv.org/abs/2502.21024>. Temporal information as fused channel, not post-hoc rerank. **+6.63% Top-1** (and +3.79 NDCG@10) on ArchivalQA. Anchors gated time-anchor-match channel.
7. **Gutierrez et al. (2025)** — *HippoRAG 2.* <https://arxiv.org/abs/2502.14802>. Dual-node phrase+passage graph with PPR seeded by dense similarity, beats MS-GraphRAG on density. Reference design for v2. Preserves event-level provenance.
8. **Voyage AI (2025)** — *rerank-2.5 / rerank-2.5-lite.* <https://blog.voyageai.com/2025/08/11/rerank-2-5/>. 32K context, instruction-following reranker. Primary v1 candidate — but verifier DOWNGRADED benchmark transfer; A/B vs Gemini 2.5 Flash listwise on logged events.
9. **Oosterhuis & de Rijke (2024)** — *Investigating the Robustness of Counterfactual Learning to Rank Models.* <https://arxiv.org/html/2404.03707>. Sparse-regime study: CLTR/IPS often fail at 5 sessions/query; 100 needed; this system has ~1. Anchors staging: GBDT at v3, contextual bandit not before v4, never CLTR-from-scratch.
10. **Kiyohara et al. (2023)** — *Off-Policy Evaluation of Ranking Policies under Diverse User Behavior.* <https://arxiv.org/pdf/2306.15098>. Defines OPE estimator and the stochasticity requirement that makes 5% score jitter from v0 a non-negotiable design choice.
11. **Wu et al. (ICLR 2025)** — *LongMemEval.* <https://arxiv.org/abs/2410.10813>. Closest methodology analogue: turn vs session granularity, abstention as first-class ability, GPT-4o judge with 97% human agreement. Templates for Recall@12, NDCG@12, Abstain F1.
12. **Carbonell & Goldstein (1998)** — *The Use of MMR for Reordering Documents.* <https://aclanthology.org/X98-1025/>. λ·Sim1 − (1−λ)·Sim2. λ=0.7 (not LangChain's 0.5) is the right Phase-3 default given upstream filtering and small candidate sets. Migration path to k-DPP at v3.
13. **Chen, Zhang & Zhou (2018)** — *Fast Greedy MAP Inference for Determinantal Point Process.* <https://arxiv.org/abs/1709.05135>. k-DPP greedy with incremental Cholesky at O(k²N) — same order as MMR. Empirical lift on Netflix Prize (1.33% vs 0.84%). Phase 3.1 migration target.
14. **Liu et al. (2023)** — *Lost in the Middle.* <https://arxiv.org/abs/2307.03172>. U-shape performance in long contexts; significant middle-degradation including for long-context-trained models. Defeats dump-the-ledger-into-Gemini as a recall mechanism; with RULER and 2026 NIAH reproductions, anchors the f7 REFUTE of long-context-as-recall.

## Completeness critic verdict

I have enough now. Task tracking is not relevant here — this is a single-pass critic review.

### 1. UNRUN MODALITY
- **Learned-sparse (SPLADE-v3) and ColBERT-style late interaction** were researched (f2) and explicitly deferred — defensible.
- **Genuine gap: learned-to-hash / binary embeddings / scalar quantization** (e.g. Matryoshka + int8/binary, Cohere/Voyage binary indexes). Synthesis discusses MRL truncation but never the quantization axis that is now standard at 10^5 facts. Low priority for v0 but a missing trade-off in `mrl_strategy`.
- **Symbolic-first then dense (entity-linker → KB-restricted dense)** not researched. The architecture has structured entities + a derivation_graph but the v0 pipeline never tries entity-resolution-as-first-stage; it folds entities into BM25 only.
- **Cross-encoder distillation / monoT5** — synthesis jumps straight to commercial rerankers (Voyage, Gemini Flash) without the open-weights baseline.

### 2. UNVERIFIED CLAIMS
- **"+0.1119 vs +0.0826" asymmetric margin** is cited as Phase A empirical; not adversarially re-verified in any f-frontier. Load-bearing for `task_type_strategy`.
- **"PREDICATE_MAX_ACTIVE=1024 active predicates, server-side filter"** — performance claim of snapshot-embedding match scaling to 1024 active predicates per query is asserted, never verified against an ANN backend's filter-pushdown cost.
- **Power-law per-kind f values (0.15/0.35/0.6)** — pure prior, not derived or cited from Wixted & Ebbesen 1997 (which fit individual subjects, not memory-kind partitions).
- **"~10^4 engagement events ≈ 6–12 months"** — arithmetic assumes 10% engagement on 10^3–10^4 recalls/day, which f8 itself flags as ambiguous (LLM-mediated two-stage credit).

### 3. UNREAD / MIS-CITED SOURCE
- **TempRetriever citation is inaccurate.** Synthesis says "+6.86 Top-1 on ArchivalQA"; the paper reports **+6.63% Top-1** (and +3.79 NDCG@10). f9 was not re-read; this is a transcription error in a top_citation. Low-stakes but indicates the citation list was not spot-checked.

### 4. UNADDRESSED CONSTRAINTS
- **Per-`embedding_model_version` index migration** is mentioned for storage but the **brief never describes how recall behaves while two versions coexist** — RRF across versions? Re-encode-on-read? Frontier f8 raises this; synthesis doesn't resolve.
- **`memory_excise` propagation through the derivation_graph** at recall time is stated as a v2 graph concern, but v0 already needs it (orphan flag isn't the same as transitive excise). Constraint partially addressed.
- **Mood / valence channel** appears in scoring but no provenance for how `query.mood` is derived from `surrounding_context`. Silent dependency on an upstream NLP component.

### 5. STAGE-1 FEASIBILITY
- v0 deliverables are mostly buildable in one sprint, **except**: "instruction-following reranker" is v1 not v0 (good), but **propensity logging requires a defined propensity model on day 1**. The synthesis says "5% score jitter for propensity diversity" — that is jitter, not a propensity distribution. v0 must also define `P(surface | candidate, score)` or OPE at v3 is dead. This is a v0 gotcha buried as a v3 prerequisite.
- The 150-event held-out label set lives at v1 but the synthesis assumes the user will label 7–8 batches of 20 — that is ~2 hours of focused work, feasible but not free.

### 6. EVAL HONESTY
- **Mostly honest.** Paired-bootstrap 90% CI excluding zero, harm-rate as hard alarm, abstain-F1, and forbidden_id negative gain are all real signals that can fail.
- **One monotonic-with-effort risk**: "Recall-log volume per day" and "embedding_model_version coverage" are listed as online metrics — both go up with effort regardless of quality. Should be labeled as health metrics, not quality metrics.
- **ECU is a weekly trend, not a level** — correctly flagged, but the synthesis doesn't define what "improving trend" means statistically (Mann-Kendall? Slope CI?). Without that, v3's success criterion "ECU improves weekly trend" is ungated.

### Recommended follow-ups
1. Fix the TempRetriever citation (6.63%, not 6.86%).
2. Add binary/int8 quantization to the MRL trade-off discussion.
3. Specify the v0 propensity distribution explicitly (e.g. Plackett-Luce over softmaxed scores with temperature), not just "5% jitter".
4. Define recall behavior across coexisting `embedding_model_version` indices.
5. Define the statistical test for "ECU trend improves."
6. Re-verify the "+0.1119 vs +0.0826" Phase A margin and the per-kind power-law `f` priors before they become load-bearing defaults.
